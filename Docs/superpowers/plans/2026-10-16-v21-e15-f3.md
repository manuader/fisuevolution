# 2.1 · E15 F3 — El momento justo · plan por tareas

> **Para agentes:** valen las «Restricciones globales» de `2026-10-16-v21-e15-f1.md`. Spec:
> `Docs/PLAN-v2-E15-valor-por-jugador.md` §4.3, §5 (la versión que sí) y §7 F3; plan general `Docs/v21/PLAN-v2.1.md`
> §3.8 y §3.10–§3.11; investigación R2 (no hay valor antes de mostrar) y R6 (bandido, A/B, retención).

**Objetivo:** cuando el jugador está en un **momento de necesidad natural** —el piso lleno, una pared de precio, el
colchón listo, la vuelta después de horas— y **hay un video cargado**, ofrecerle a la vista algo concreto a cambio del
video, con «No, gracias». Un bandido Thompson elige **qué oferta, de qué tamaño y cuándo** entre brazos que llegan por
la config remota, siempre con un brazo de control y con la retención como límite (que aplica F7 apagando brazos).

**Lo que NO es F3 (spec §5):** nada fabrica el momento. Los detectores leen el estado del juego; ninguno lo cambia. No
hay «anuncio caro cargado» (R2; V4: sin MAX en la 2.1): la condición es «hay un video cargado» y, como mucho, el promedio del ledger del
jugador (que ya está en su segmento).

**Arquitectura:** EK puro para detectar, decidir y muestrear (`Moments/`); la app arma una foto del estado cada pocos
segundos, pregunta al planificador y muestra una tarjeta con `RewardedOfferButton` (así el embudo de F0 la cuenta
sola). Los brazos y sus priors vienen en la sección `moments` de la config de F1; el teléfono suma sus observaciones.

## Contratos

### C1 — Momentos (EK, T1)

```swift
public enum NeedMoment: String, Codable, Sendable, CaseIterable {
    case floorFull = "floor_full"          // no hay lugar libre en el piso activo
    case priceWall = "price_wall"          // la próxima contratación tarda más de N minutos de ingreso
    case mattressReady = "mattress_ready"  // el colchón gratis del tablero está listo y sin cobrar
    case backOffline = "back_offline"      // volvió después de más de N minutos afuera
}

public struct NeedSnapshot: Sendable, Equatable {
    public var freeSlots: Int
    public var nextHireCost: Double
    public var incomePerSecond: Double
    public var mattressReady: Bool
    public var secondsAwayOnReturn: Double?   // sólo en el primer snapshot de la vuelta
    public var uiCoversBoard: Bool            // con un pop-up, hoja o tutorial encima: no hay momento
    public var tutorialActive: Bool
}
```

`NeedDetector.moments(_:thresholds:) -> [NeedMoment]`, en orden de prioridad. `uiCoversBoard` o `tutorialActive` →
ninguno. Los umbrales (`priceWallMinutes`, `backOfflineMinutes`) vienen de C3.

### C2 — El bandido (EK, T2)

- `ThompsonBandit`: brazos con `Beta(α, β)`; `choose(eligible:, rng:)` muestrea cada uno y elige el mayor;
  `observe(arm:, success:)`. Muestreo de Beta por dos Gamma (Marsaglia-Tsang) con un `RandomNumberGenerator` inyectado
  (`SplitMix64` propio con semilla): **determinista en tests**.
- El brazo de control (`isControl`) no muestra nada; siempre elegible; su tasa la mide F7 contra la retención.

### C3 — `MomentsConfig` (EK, T3; sección `moments`)

```json
{
  "version": "seed-2026-10-16",
  "thresholds": { "priceWallMinutes": 8, "backOfflineMinutes": 120 },
  "caps": { "maxPerHour": 3, "minSecondsBetween": 600, "cooldownAfterDeclineSeconds": 1200, "maxPerSession": 6 },
  "arms": [
    { "id": "pw_small", "moment": "price_wall", "reward": {"kind": "coinsSeconds", "seconds": 300}, "alpha": 1, "beta": 1, "segments": ["low","mid","high"] },
    { "id": "pw_big",   "moment": "price_wall", "reward": {"kind": "coinsSeconds", "seconds": 600}, "alpha": 1, "beta": 1, "segments": ["mid","high"] },
    { "id": "ff_merge", "moment": "floor_full", "reward": {"kind": "mergeAll"},                     "alpha": 1, "beta": 1, "segments": ["low","mid","high"] },
    { "id": "control",  "moment": "*", "control": true, "alpha": 1, "beta": 1 }
  ]
}
```

- **Topes en el código** (`MomentsConfig.Caps.hard`): `maxPerHour ≤ 4`, `minSecondsBetween ≥ 300`,
  `cooldownAfterDeclineSeconds ≥ 600`, `maxPerSession ≤ 8`, recompensa de plata ≤ `MomentsConfig.maxRewardSeconds`
  (la fija F2-T5 con el sim). Fuera de tope → archivo inválido (todo o nada).
- `reward` usa `RewardSpec` existente (nada de premios nuevos). Un `kind` que el juego no puede pagar ahora (`mergeAll`
  sin nada para fusionar) hace inelegible al brazo.
- `mattress_ready` y `back_offline` **no tienen brazos propios en la semilla**: ya existen sus ofertas (el ×N del
  colchón y del offline, F2); F3 sólo les pone `ctx` en el embudo. Pueden ganar brazos por config.
- `segments`: el brazo sólo es elegible para esos segmentos; **`base` nunca ve ofertas del momento**.

### C4 — El planificador (EK, T3)

`MomentOfferPlanner.next(moments:, segment:, adReady:, history:, now:, config:, bandit:, rng:) -> MomentDecision`
(`.none` | `.control(armId)` | `.offer(armId, moment, reward)`):
`segment == .base` → `.none`; `!adReady` → `.none` (y no consume frecuencia); topes de C3 sobre `history`; entre los
brazos elegibles del primer momento, el bandido elige (el control incluido).

## Dudas (default si nadie dice otra cosa)

1. **Bloque de anuncio:** se reutiliza `gifts` (sin trámites en AdMob, regla del dueño). **Default:** así; el ledger lo
   distingue por `site`.
2. **Premios de los brazos:** sólo `RewardSpec` existentes. **Default:** plata en segundos y «Fusionar todo».
3. **El control** se elige como cualquier brazo. **Default:** prior `α=β=1`; F7 fija una proporción mínima si hace
   falta (p. ej. 10 %) cuando haya datos.
4. **Aprendizaje global:** los priors de la config los calcula F7-T3 con el embudo agregado (por brazo, no por jugador).
