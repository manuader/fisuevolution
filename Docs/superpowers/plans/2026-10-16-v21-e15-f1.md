# 2.1 · E15 F1 — VEJ v1 con reglas · plan por tareas

> **Para agentes:** 2.1, rama base `version-2.1`; cada tarea en su worktree `.claude/worktrees.nosync/v21-<fase>-tN`
> (rama `v21/<fase>-tN`) desde la BASE que da el despacho. **Regla del dueño: no se compila por tarea** (ver
> «Restricciones globales»). Spec: `Docs/PLAN-v2-E15-valor-por-jugador.md` §4.1 y §7 F1; plan general:
> `Docs/v21/PLAN-v2.1.md` (§3 decisiones, §4 gates). Tablero: `tasks-v21.md`.

**Decisiones del dueño que aplican (V4–V12, `PLAN-v2.1.md` §0):** V5 (tabla semilla, sin exportes), V9 (TCF
{1,5,6,8,9,10}), V10 (sin edad; señal de menor → `base`), V11 (sin abogado por ahora: **la personalización sale apagada**
hasta T9). No se re-preguntan.

**Objetivo:** que el teléfono sepa **en qué segmento está cada jugador** (`base`, `low`, `mid`, `high`) y cuánto vale
en promedio un video suyo, con reglas deterministas y tablas que llegan por configuración remota; con un interruptor
que vuelve todo a `base`, y sin cambiar todavía nada de lo que el jugador vive (las palancas son F2, F3 y F5).

**Arquitectura:** el cálculo es puro y vive en EconomyKit (`Personalization/`). La app arma las entradas (ledger de F0,
compras, sesiones, país de la tienda, modelo del dispositivo), carga las tablas (Supabase RPC → caché → respaldo del
bundle), aplica la compuerta (interruptor ∧ consentimiento ∧ no UI test) y expone `GameState.segment`. El segmento se
guarda en `Application Support`, no en el save.

## Contratos

### C1 — Segmento y estimación (EK, T1)

```swift
public enum PlayerSegment: String, Codable, Sendable, CaseIterable, Comparable { case base, low, mid, high }

public struct PlayerValueInputs: Sendable, Equatable {
    public var storefront: String?            // ISO alfa-3 (DeviceContext), nil si no se sabe
    public var deviceModel: String?           // utsname.machine, p. ej. "iPhone16,2"
    public var rewardedCount: Int             // ledger.stats(.rewarded).count
    public var averageRewardedMicros: Int64   // ledger.averageRewardedMicros
    public var recentRewardedMicros: Int64    // ledger.recentMicros(format: .rewarded)
    public var hasPurchased: Bool             // meta.creditedPurchases no vacío
    public var sessionsLast7Days: Int
    public var meanSessionSeconds: Double
    public var videosWatchedEver: Int         // meta.stats.videosWatchedEver
}

public struct PlayerValueEstimate: Sendable, Equatable {
    public let segment: PlayerSegment         // nunca .base: .base lo decide la compuerta, no las reglas
    public let expectedMicrosPerVideo: Int64
    public let score: Double                  // 0…1, para los umbrales y para el panel
    public let tablesVersion: String
}
```

### C2 — Las tablas (`PlayerValueTables`, EK, T1; JSON en T2)

```json
{
  "version": "seed-2026-10-16",
  "countryTier": {"USA": 1, "GBR": 1, "ARG": 3, "…": 2},
  "defaultCountryTier": 3,
  "tierMicros": {"1": 18000, "2": 6000, "3": 1500},
  "deviceTier": {"iPhone17,": 1, "iPhone16,": 1, "iPhone15,": 2, "iPhone14,": 2, "iPad": 2},
  "defaultDeviceTier": 3,
  "minOwnImpressions": 5,
  "ownWeight": 0.7,
  "engagement": {"sessionsFor1": 14, "secondsFor1": 900},
  "weights": {"value": 0.6, "engagement": 0.25, "purchase": 0.15},
  "thresholds": {"mid": 0.35, "high": 0.7},
  "hysteresis": 0.05
}
```

- `deviceTier` se resuelve por **prefijo más largo** del identificador (`iPhone16,2` → `iPhone16,`).
- `expectedMicrosPerVideo`: con `rewardedCount ≥ minOwnImpressions`, `ownWeight × promedio propio + (1 − ownWeight) ×
  tierMicros[país]`; si no, `tierMicros[país]` ajustado por el tier del dispositivo (×1,0 / ×0,8 / ×0,6).
- `score` = `weights.value × norm(expected) + weights.engagement × norm(sesiones, duración) + weights.purchase ×
  (compró ? 1 : 0)`, con `norm` saturando en 1 (`tierMicros["1"]`, `sessionsFor1`, `secondsFor1`).
- Segmento: `score < mid` → `low`; `< high` → `mid`; si no, `high`. **Histéresis:** si hay un segmento anterior, para
  cambiar de escalón el score tiene que pasar el umbral por `hysteresis`, y nunca salta más de un escalón por día.
- `validate()` de todo o nada: pesos ≥ 0 que suman 1 ± 0,001; `0 < mid < high < 1`; `tierMicros` positivos; claves de
  país `^[A-Z]{3}$`; `0 ≤ ownWeight ≤ 1`; `hysteresis` en `[0, 0,2]`. Un archivo inválido no se usa.

### C3 — La config remota (envoltorio, app, T4; SQL, T3)

`personalization_config()` (RPC, `anon`) devuelve `null` con `personalization_enabled = false`, y si no:

```json
{ "version": 3, "sections": { "player_value": {…C2…}, "segments": {…F2…}, "moments": {…F3…} } }
```

Cada fase decodifica **su** sección (`PersonalizationConfig.section(_:as:)`); una sección que falta o no valida deja
esa fase en `base`, sin tocar a las otras. Tope del cuerpo: 64 KB.

### C4 — La compuerta (T4)

`PersonalizationGate.isOpen` = interruptor remoto `true` explícito **∧** consentimiento de personalización (C5)
**∧** no es UI test (salvo `--uitest-segment <s>`, que fuerza el segmento y saltea todo) **∧** no hay señal de menor de edad (UMP/`tagForUnderAgeOfConsent`) **∧** no es `DEBUG` salvo
`--personalization-debug`. Cerrada → `base`.

### C5 — El consentimiento para personalizar (R5; T4)

`PersonalizationConsent.allows(gdprApplies:purposeConsents:umpCanRequestAds:umpSaysNotRequired:)`: la misma forma que
`TelemetryConsent` pero con los propósitos TCF **1, 5, 6, 8, 9, 10** cuando `gdprApplies == 1`. Fuera del RGPD,
igual que F0. **Decidido por el dueño (V9)**; `[VERIFICAR CON ABOGADO]` en T9: si la lista cambia, es esta constante
y su test.

### C6 — Eventos nuevos de telemetría (T6; UNA migración nueva para toda la 2.1; R4)
